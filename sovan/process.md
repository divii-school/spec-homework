## Notes

- **Round 1 and Round 2 written together**: Because Round 1 was overdue and Round 2 was announced the same day, I wrote both rounds in a single pass and documented the changes in the change log (v1.0 → v1.1). The v1.1 entry lists every ID that was added or modified for the paid plan.
- **Design decisions I made** (not given in the brief): free tier limit (3/month), ATS scoring dimensions and weights (7 dimensions totalling 100), max file size (5 MB), data retention (90 days), AI provider (OpenAI GPT-4o), file storage (AWS S3; upload through the API, presigned URLs for download only — fixed in v1.2), PDF generation (Puppeteer + Handlebars), currency storage (paise to avoid float errors).
- **v1.2 (Oct 28) — what the build test taught me**: the builder logged 18 guesses, most from three gaps: (1) I described analysis as both synchronous (API-005 returned 200 inline) and queued (FR-017 "re-queues", FR-010 "async via queue") without ever defining the queue; (2) CMP-004 said "presigned URLs for upload" while Flow 1 and API-001 used multipart through the API; (3) FR-011 said "the user's tier changes" but no table or column held a tier, nothing said how it expired, and `GET /analyses/compare` was not actually gated. Fix: one explicit decision per gap, recorded in a new §4.6 decisions table (D-01..D-03) and referenced from every affected ID. Lesson: when a spec mentions a mechanism (queue, cache, tier) it must have a home — a component ID, a table/column or a key name — or the builder will invent one.
- **Commit cadence**: round 1 + 2 landed in one push on Oct 22, which the reviewer flagged. From v1.2 on, changes are committed in small steps (the spec revision and the process notes as separate commits, further revisions per decision) so the history shows the work. v1.2 was prepared on branch `spec/sovan-v1.2` while `spec.md` was frozen for scoring, and merged only after the freeze was lifted.
