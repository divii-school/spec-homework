## Build test of `spec.md` (v0.9, read in full, all 3,263 lines)

I read only `sachin/spec.md`. I opened no other file and changed nothing. The list is ordered by impact, highest first.

1. **FR-016 criterion 3 vs FR-016 c2 / TBL-009 / 4.6.1. CONTRADICTION (high).**
   - FR-016 c3 says the PDF "contains no contact details and no name".
   - FR-016 c2 says the PDF contains the "visible suggestions per FR-012". Each suggestion carries `original_line`, which TBL-009 defines as "as returned by the AI: a substring of the redacted text that was sent". The AI's dimension explanations also go into the PDF.
   - Redaction (4.6.1) removes only email, URL and phone. TBL-005 stores the text "normalised, **not** redacted". There is no user table (A-1), so the module never knows the name and cannot filter it out.
   - "No name" therefore cannot be implemented, and `ReportRendererTest` ("no name or contact data") cannot be passed reliably.
   - Fix: drop "no name" (say quoted resume lines appear as written), or define a rule such as leaving `originalLine` out of the PDF.

2. **FR-018 / API-006 vs API-007, concurrency. GUESS (high).**
   - 4.3.6 says deleting a resume happens "after checking that none of its analyses is QUEUED/RUNNING", with no lock.
   - API-007 checks the resume outside its locked transaction, then inserts the analysis.
   - A delete running at the same time either cascades a fresh `QUEUED` analysis away (breaks FR-018 c2, and the quota unit is lost because it is never released), or makes the insert fail on the foreign key (500).
   - Fix: API-006 takes the per-user advisory lock and locks the resume row `FOR UPDATE` before its check. API-007 re-checks that the resume exists inside its locked transaction, else 404.

3. **Section 4 run-mode table vs 4.8.2 local setup. CONTRADICTION (medium-high).**
   - `api` runs its "management server on 8081".
   - `worker` uses "`server.port` = `management.server.port` = 8081".
   - Locally, "the API, the worker and the migration run on the host with `scripts/run-local.sh`", and 4.8.2 lists no port override.
   - Running api and worker together on one machine therefore fails with "address already in use".
   - Fix: add a local row (for example `MANAGEMENT_SERVER_PORT`/`SERVER_PORT` = 8082 for `run-local.sh worker`).

4. **TBL-011 `completed_at`. GUESS (medium).**
   - It is set by "whichever step removes the last one … after checking that no row with this `erasure_record_id` is left in either table".
   - The CMP-015 and CMP-021 jobs both run every 10 minutes, and no lock is specified. Two transactions deleting the last row of each table at the same time each see the other's row, so neither sets `completed_at`.
   - Once both rows are gone nothing retries, and no alert covers it.
   - Fix: every path that may set `completed_at` first runs `SELECT … FROM erasure_record WHERE id = ? FOR UPDATE`.

5. **CR-013 / 3.4, frontend handling per error code. GUESS (medium).**
   - CR-013 says "The frontend shows its own translated text per code", but 3.4 gives only `errors.SERVER_BUSY`.
   - Not given:
     - the text and UI action for the other 25 codes (for example `CONSENT_REQUIRED` → show the notice? `RESUME_EXPIRED` → re-upload prompt?);
     - the three `failureReason` values;
     - the "four Pro benefits" (FR-030 states d/e);
     - category display names (5.5);
     - the FREE PDF footer line (FR-016 c4).
   - Fix: add `errors.<CODE>`, `analysis.failure.<REASON>` and `pro.benefits.*` keys, plus the UI action per code, to 3.4.

6. **2.2 / CMP-001, screen composition. GUESS (medium-low).**
   - FR-015 needs a picker for existing resumes, but no page is assigned to API-005 or API-006.
   - No page owns the delete-analysis (API-010) or download (API-011) controls.
   - How the consent gate appears (inline on the upload page or a redirect to `/privacy`) is not said.
   - Whether the user types "DELETE" for API-013, or the UI sends it after a dialog, is not said.
   - Fix: a short per-page table listing sections, API calls and actions.

7. **API-016 vs 3.4, privacy notice versioning. CONTRADICTION (medium-low).**
   - API-016 says "the UI shows the notice text for this version from its message files".
   - The 3.4 keys are not versioned (`privacy.notice.purpose` …), yet "Changing a text … is a new notice version".
   - The version lives only in the API's `PRIVACY_NOTICE_VERSION`, so after a version change the web can show old text that the user then accepts as the new version.
   - Fix: key the texts by version, and have the UI refuse to show or accept a version it has no texts for.

8. **4.7, ShedLock stop rule. GUESS (low-medium).**
   - A job "stops when [remaining lock time] is less than the time one batch may take (a batch's statement timeout …)".
   - No statement timeout is defined anywhere, and there are no S3 client timeouts for the storage-deletion job's per-row budget.
   - Fix: add `app.jobs.statement-timeout` and the S3 call/attempt timeouts to 4.7.

9. **CR-010 / CMP-009 / 4.3.4, request id on re-queue. GUESS (low).**
   - Stream messages "carry … `analysisId` and `requestId`", and the `requestId` is "passed to background jobs".
   - TBL-006 has no request id column, so the sweeper's re-queue `XADD` has no original `requestId` to send.
   - Fix: add `analysis.request_id`, or state that the sweeper sends a new UUID.

10. **Section 5 intro / 5.6 vs 5.2, contents of V1. CONTRADICTION (low).**
    - "`V1__init.sql` creates the v0.3 schema (TBL-001 – TBL-015)", and 5.6 says "The old checks allow only FREE and PREMIUM".
    - TBL-006 and TBL-014 give only the `('FREE','PRO')` CHECKs, and the v0.3 schema is written nowhere.
    - Fix: state that V1 equals 5.2 except those two CHECKs use `('FREE','PREMIUM')` (or fold V3 into V1, since nothing has been released).
